# 组织角色委派操作

全局管理员在“组织与角色”创建组织角色，选择“组织角色定义与分配（受自身能力上限约束）”及允许继续委派的其他能力，再分配给组织内操作员。只有 roles:manage 而没有其他能力的操作员只能委派角色管理本身，不能授予应用访问或站点管理。

组织操作员重新登录后可进入“组织与角色”。该入口只显示自身组织，不提供创建/删除组织或全局管理员操作。创建角色时只出现自己持有的能力选项；更高权限的现有角色和成员不可编辑/分配。最小成员目录用于分配角色，不需另外授予成员密码管理能力。

修改角色或成员角色会让受影响成员所有设备退出，已有 HTTP/WS/SSE 关闭。给自己降权也会让自己退出。先保留一个全局恢复管理员，再安排组织内委派；组织操作员无法修改全局管理员。

权限限制同样由 API 校验：POST/PATCH/DELETE `/api/roles`、PATCH `/api/users/{id}/role` 需要 roles:manage；目标必须在本组织，原有和新权限都不超过当前操作员。`GET /api/role-members` 返回最小目录，`GET /api/roles` 的 manageable 标记用于界面展示。不要以缓存的角色列表作为权限判断依据。

需要更高能力时由全局管理员调整操作员的角色，旧设备会被撤销，需要重新登录。角色管理不会自动赋予成员密码重置、OIDC 绑定或账号禁用权限。状态备份 v10 包含新能力，恢复历史备份后复核委派关系；旧角色不会因升级自动获得它。
