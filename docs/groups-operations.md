# 用户组和邀请操作手册

## 统一分配应用访问

管理员打开“用户组与邀请”，点击“创建用户组”，选择成员、整站和单独应用授权并保存。组权限只控制应用访问，不能授予管理员角色。

直接授权与组授权取并集。例如用户直接获得 A，组获得 B，则两者都可访问；取消用户表中的 B 并不会覆盖组赋予的 B。要收回 B，需同时核对所有直接/组授权来源。

“编辑用户组”替换成员和权限。保存后立即关闭失去授权的应用连接，保留控制台及其他仍获授权连接。删除组保留用户账号。删除站点/应用/成员时引用会在同一事务清理，无需手动改数据库。

界面周期刷新；其他浏览器接受邀请后，组成员显示可在下一次刷新或重新进入此页时更新。鉴权不依赖页面刷新，每次应用请求都读取最新权限。

## 邀请成员自行设置密码

1. 点击“邀请成员”，填写未占用用户名，选择有效小时（1–168，默认 72）、直接授权和加入的组。
2. 保存后复制页面显示的链接，通过可信渠道交给受邀者。本系统不会自动发送邮件或消息，链接只展示一次，列表不能再次取回明文。
3. 成员打开链接，确认用户名，设置并确认密码后加入。密码至少 12 字节、最多 72 字节；接受后切换至该成员账号。
4. 管理员核对组成员与访问范围。邀请已消费后从待使用列表移除，旧链接不能再次使用。

链接是临时凭据，不应贴到公开工单、截图或日志。页面读取 fragment 后清除地址栏中的 token，但浏览器/剪贴板等外部系统仍需按凭据管理。若链接遗失或泄漏，在待使用邀请行点击“撤销邀请”后重新创建。

失效/过期/已使用的链接会显示统一错误。过期邀请在创建新邀请时清理并释放用户名；也可手动撤销。不能邀请现有账号来替换密码，密码维护继续使用原有流程。OIDC 专用成员继续通过管理员显式绑定创建，不经本地密码邀请转换。

## 升级、备份与恢复

升级前停止 Server，用旧二进制导出并验证 backup，另保留停机目录。SQLite v1/v2 首次打开时事务升级到 v3；JSON 自动兼容新增可选字段。升级失败不会留下部分 schema。旧二进制不能读取 v3，回滚恢复匹配的旧状态和程序。

新导出 backup v3，可读取 v1/v2/v3。正常重启、JSON→SQLite 迁移会保留未使用邀请。执行 `storage restore` 时，所有 pending 邀请会被清空，以防历史备份复活已使用 token；已有用户、组及其成员关系保留。恢复后重新签发需要的邀请。

备份包含密码/Agent/token 散列和授权信息，不加密。仅有校验和不代表来源可信，勿恢复不可信备份。

## 验收

- 创建只授予一个应用的组；成员能打开该应用，但不能通过兄弟应用 ID 访问其他服务。
- 从独立浏览器接受邀请，确认角色为成员、无需管理员提供密码；再次打开链接失败。
- 收回组权限，旧应用页面/长连接立即失效，成员控制台仍可登录。
- 撤销未用邀请，链接不能使用；并发使用同一个 token 只能成功一次。
- 在 JSON/SQLite 两种后端分别运行 `make test` 与 `pnpm --dir web run test:e2e`，真实 Keycloak 验证仍按上一批手册运行。

本批的组是工作区内的授权集合，尚未引入组织租户隔离或自定义管理角色；下一批将为资源所有权、管理员作用域及审计可见性建立独立边界。
