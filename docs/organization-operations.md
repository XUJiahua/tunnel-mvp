# 组织与角色操作手册

## 升级和旧资源

停止 Server 并按 [存储手册](storage-operations.md)备份；SQLite 会事务升级到 schema v4，旧用户/站点/应用保留在默认组织。JSON 旧文件可直接读取；新字段在下一次写入保存。默认组织不删除。需要回滚时恢复旧二进制和升级前数据，不用旧程序覆盖新格式。

用户名和 OIDC 身份全局唯一；成员只有一个组织。全局管理员独立管理整个控制面，不属于命名组织。原成员无需改账号或重新授权；Server 重启仍要求重新登录。

## 创建组织和操作者

1. 全局管理员进入“组织与角色”，创建组织。左侧“组织范围”选择该组织，随后接入站点、添加应用和创建成员；新对象归属当前组织。
2. 在“组织与角色”选择“角色所属组织”，填写名称并勾选需要的能力。组织管理员可选择全部能力，应用运维可以只选“应用管理与诊断”；需要进入应用时另选“访问组织内全部应用”或给账号直接/组授权。
3. 在“成员角色”中给对应组织的成员分配角色。确认后该成员全部旧设备退出，要求重新登录。组织操作者无法看到全局管理员、全局设备或指标入口；显式获得 roles:manage 后可按 [角色委派手册](delegated-role-operations.md) 管理自身能力范围内的角色。
4. 用第二个浏览器实际验证所属组织资源、管理入口和应用访问。不要依赖全局管理员视角完成验收。

成员/组管理能力允许为本组织成员分配应用访问；站点令牌与目标配置管理人员应按站点运维人员信任。只需访问应用的成员无需管理角色，继续使用直接授权或用户组。组织角色持有者的账号管理由全局管理员执行，普通成员管理员不能重置/禁用另一个角色账号。

## 缩权、移交和删除

编辑角色能力或清空成员角色都会注销受影响账号全部设备并关闭 HTTP/WS/SSE。删除角色保留成员及直接/组授权；重新登录后验证不再能调用旧管理 API。角色不允许改变所属组织，资源同样不能跨组织移动；跨组织移交应重新创建成员/站点/应用并重新授权。

删除组织前清理邀请、组、成员、应用/站点与角色；非空组织拒绝删除。删除站点会连带删除该站点应用，沿用原有确认流程。删除组织不影响其他组织。

全局管理员仍必须保留最后一个本地恢复账号。命名组织成员不能直接提升为全局管理员；需要单独创建全局管理员账号，见 [管理员生命周期](administrator-operations.md)。

## 审计与排查

组织审计只显示带本组织 organizationID 的新记录；旧历史、未知归属和全局管理记录由全局管理员查看。删除资源事件保留原组织。Prometheus 和全部设备清单仍为全局运维接口，不向组织操作者暴露。

遇到 403 先检查当前角色能力，遇到资源不存在检查组织归属。应用编辑能力不等于应用访问，“打开”禁用时补应用授权后重新进入。跨组织资源 ID 即使可猜到也不能读取、诊断、修改或授权。邀请链接接受后创建在邀请所属组织，不能携带角色字段提升管理权。

验收用 JSON/SQLite 分别运行 `make test` 和构建后的 `pnpm --dir web run test:e2e`。真实 IdP 验收还需按 [会话手册](session-operations.md)配置 KEYCLOAK_HOME/Java 21；普通浏览器任务跳过该项不代表完成真实 IdP 验证。
