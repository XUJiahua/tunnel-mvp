# 审计轮转与 schema v3 操作

本批启动时将 monitor.db v1/v2 事务升级为 v3；授权状态仍为 v10，运维归档格式仍为 v1。升级前按既有流程停机导出授权备份和运维归档，保留配对副本。旧程序不识别 monitor v3，回退需用旧版本可读的配对备份。

正常轮转只删除过期文件对应的事件索引，不重新读取所有保留日志。保留 event ID 不变，但每次轮转仍使分页游标失效，界面需从最新记录重新查询。文件数包含 active，跳过行计数按保留文件统计，过期文件的跳过计数一并消失。

不要在 Server 运行时编辑、拼接、移动或截断 JSONL/monitor.db。发现额外字节、索引脏状态或轮转失败时会从当前文件集重建；索引未能恢复时审计查询返回 503。检查磁盘空间、权限、文件类型和 `tunnel_audit_index_errors_total`，修复后重新查询；不要删除 JSONL 来消除索引错误。

导出/校验运维归档会额外验证 monitor 表结构、审计来源外键和槽范围。若提示孤立来源或损坏，先保留原目录，恢复到可运行状态并让 Server 从 JSONL 重建，停机后再导出；不能通过手改 manifest 校验和把坏索引包装成有效备份。

重建仍可能与总日志量成正比；巨大过期文件的索引删除也需要事务时间。本批减少健康轮转的重复解析，不承诺所有恢复/轮转耗时恒定。
