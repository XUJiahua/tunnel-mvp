# HA-4 共享观测与排空（实施中）

保留 PostgreSQL 基础 schema v3、portable 配置 v10、monitor.db 基础 schema v3 和 cluster-v1 流协议。共享审计、健康样本、节点报告使用独立 observation extension v1。旧 HA-3 节点可继续路由，但没有观测报告，控制台必须显示覆盖不完整；只有全体节点报告新鲜才可判断集群观测覆盖。

每个本地 monitor.db 绑定稳定 sourceID 和 nodeID。新审计在调用者字段之后盖章 eventID、nodeID、nodeEpoch、sourceID，先追加并 fsync JSONL，再在同一 SQLite FULL 事务内写索引和持久队列。健康样本与队列同事务。发布先提交 PostgreSQL，再确认捕获的本地队列序号。重复 ID 且内容相同为幂等重放；相同 ID 不同内容整体回滚。来源不能换绑节点。队列独立于轮转文件，已排队记录不因轮转删除。

旧 JSONL 没有事件 ID，不能通过内容哈希合并相同记录。启动时保留每一行，生成完整快照及结束标记；数据库只显示最近完成的快照。快照替换或审计保留清理改变分页 epoch，旧游标返回 409。新 UUID 事件跨快照稳定。共享保留默认 7 天、审计 100000 条、样本每应用 1440 / 全局 100000 条；审计按接收时间到期，健康样本按发生时间到期。

共享查询在同一 Repeatable Read 事务内重新校验会话、身份新鲜度、当前角色和应用配置。全局管理员看全部审计，委派角色限定组织；未知组织旧记录仅全局管理员可见。健康查询只返回当前 profile。数据库错误不回退到本地不完整结果。共享发布锁独立于配置/认证行锁，批量插入后逐批核对冲突。

`cluster.observationBufferMB` 默认 256 MiB，可设 16–2048。启动会将本地保留记录重新排队，以支持新数据库配对恢复；超过容量启动失败，需提高容量或按保留策略准备归档。运行时队列满，审计保留 JSONL 并计数，后续按小页补录；健康样本写入整体失败并计数，不宣称零丢失。监控存储错误及 enqueueErrors 必须告警。磁盘满或写入失败仍可能损失尚未持久化数据。

排空 API 必须指定实际 nodeID，防止 LB 错投；事务内重新校验全局管理员后撤销该节点路由 ready。心跳不能重新发布已排空路由。排空时 healthz 返回 503、新应用和 Agent 连接拒绝；管理 API 保留用于解除排空。既有 WS/SSE 和 Agent 通道继续授权重证，正常完成或撤权后关闭。排空不是强制迁移，也不自动终止长流；停止节点前要检查活动通道，设置业务允许的等待上限。

本分支尚待 PostgreSQL 15/18、真实双节点、浏览器、混合版本与备份恢复验收。未完成的演练不记为通过。
