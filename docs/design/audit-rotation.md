# 审计轮转的增量索引

monitor.db schema v3 为每个保留 JSONL 文件分配稳定 source ID，并在 audit_events 中引用它；audit_sources 仅维护当前轮转槽和该文件的跳过行数。JSONL 继续是事实来源，不把 SQLite 索引作为独立审计账本。

健康运行时：先在 auditMu 下完成文件轮转，再在一个 SQLite 事务中删除过期 source 的事件、调整少量 source 槽、创建新 active source 和更新文件数/跳过计数。保留事件行及 ID 不重新解析/插入，索引 source_id 加速过期删除。游标 epoch 仍在每次轮转改变，旧分页返回 409，避免保留边界上的隐式重漏。

启动、脏索引、文件轮转失败或增量 SQL 失败时回退到所有配置保留文件的完整事务重建；失败明确返回 503，不返回残缺成功。运行期跟踪 active 文件预期字节数，发现额外写入/截断时标记脏并从 JSONL 修复。active 文件缺失、符号链接或非普通文件会使重建失败；不支持其他进程同时修改审计文件。

source ID 和预期字节数缓存只在事务成功后更新，写失败保留脏标记。保留期删除的是整份过期源的索引行；跳过计数随对应源过期，而不是无限累计。超长/无效/非 UTF-8 行保留在源文件但不进入索引。

v1/v2 → v3 在单事务内创建来源表并重建带外键的事件表，保留已有事件/ID；启动随后从实际 JSONL 重建。外键始终启用，授权状态 schema/backup v10 不变。运维归档 manifest 仍为 v1，接受 monitor v1/v2/v3，并校验表结构、外键及来源槽范围。

验收使用触发器禁止重写保留标记，证明健康轮转不做全量索引；检查 ID 保留、到期删除与文件/跳过计数。覆盖有数据的 v2 升级、增量失败回退、来源孤立时归档拒绝、原有 2 MiB 页预算/组织隔离/游标失效；浏览器在首次登录触发真实文件轮转，继续查询旧源和分页，再执行停机归档/跨后端恢复。
