# 资源定向读取

本批增加可选 `state.ResourceReader`：按 ID 查站点、按 ID/自定义域名查应用。Repository 原有 Snapshot/Update 契约保留，便于旧实现继续工作。控制面站点/应用点查和网关 host 路由使用此接口；没有该接口的旧 Repository 使用原快照逻辑。

## 一致性与失败

Store 读锁与 Update 写锁排序。每次点查返回一个完整已提交实体，不能看到事务中已删除但未重新插入的行。多个独立点查不是一个共同事务快照；控制面原有 accessMu 继续把管理写入和请求鉴权/路由排序。SQL 错误显式返回给调用方，控制面的既有 bool 查找入口拒绝匹配，不能回退到可能过时的内存快照。

当前 Site/Service 字段都是值字段，结果不会暴露内存快照引用。以后增加 slice/map/pointer 可变字段时须补复制语义。JSON 只扫描相关实体集合，不序列化/反序列化整个状态。SQLite 使用参数化 SELECT，ID 走主键，自定义域名走派生的非空 partial index。

## 索引与兼容

新增 `services_custom_domain` 非唯一索引，不改变已存在的自定义域名唯一性语义（仍由 Validate/原子 Update 校验）。当前及旧库完成数据验证/迁移后自动创建，启动过程持目录锁。索引可从实体重建，不升级授权 schema/backup v10，不移除目录独占锁，不增加多写者或 HA 能力。

没有查询缓存。资源修改、域名更换、迁移、删除和失败事务之后直接读取数据库已提交值。SQL 读取失败时资源路由拒绝匹配；当前 HTTP 查找接口会表现为资源不存在，运维仍应检查数据库文件、权限及底层错误。列表/授权、用户/组/角色等路径仍使用内存快照，写入前全量校验仍为 O(N)，不能声称已实现全部增量 SQL 查询或端到端 O(1) 请求。

## 验证与基准

测试比较完整实体字段，覆盖 JSON/SQLite 的域名替换、失败验证不生效、SQLite durable trigger 回滚、连接失败不回退、关闭后拒绝读取、并发读写、旧库启动重建索引及实际查询计划。旧 schema 夹具在删除 custom_domain 前去掉派生索引，保持真实旧布局。

真实浏览器在双 Agent/挂载路径场景中完成登录、上传、WS/SSE 和迁移，再在线更换域名：旧入口必须 404，新 launch 使用新域名并完成上游登录。两套存储均需运行完整浏览器回归。

本地受控基准包含 1001 用户、1000 应用，100 次操作 × 3 轮。完整快照扫描 ID 为 2.91–3.14 ms/op、约 2.04–2.24 MB/op；SQL ID 点查为 17.5–20.0 µs/op、1608 B/op，域名点查为 19.7–27.2 µs/op、1640 B/op。原始记录见 [resource-queries.txt](../capacity/resource-queries.txt)。这是单个查询对比，不能用来推断整个网关吞吐提升比例。
