# 当前用户鉴权投影

`state.UserReader.UserContext(id)` 返回用于鉴权的部分 State：一个用户、其当前角色、包含该用户的组。它不能用于写入或完整 Validate，不含全部用户、资源、邀请、组织等目录。控制面 `store.user` 统一使用该接口，并沿用 effectiveUser 计算直接授权与组授权并集、组织角色能力。没有该接口的旧 Repository 保留快照兼容。

## 一致性

Store 读锁覆盖投影全部 SELECT，与 Update/Close 写锁排序。用户字段、直接授权、角色和组都来自同一个已提交版本；不能看到角色已改而组尚未改的中间状态。控制面 accessMu 仍负责管理写入、当前请求授权及活动流撤销的排序。没有用户鉴权缓存。

JSON 在锁内选出关联实体后只复制该投影；身份指针、授权/角色/组切片全部与内部状态分离。SQLite 按用户主键查询，按 user_id/position 查询直接站点/应用授权，按角色主键查询 payload，并按派生成员索引连接组且保持组位置顺序。所有 SQL 参数化，角色和组 payload 的 ID/组织必须与用户相符。

只有所有查询成功后才返回可用投影。用户不存在正常返回 not-found；角色缺失、组读取失败、数据库错误或已关闭不会回退旧快照，控制面拒绝鉴权。绑定/禁用/角色/授权更新仍走原有原子 Update 和撤销逻辑。

## 查询与运行边界

组 JSON payload 仍为规范数据，成员筛选已改为同事务派生索引；登录名/IdP 和管理目录也已使用独立查询接口，见 [存储查询](storage-queries.md)。写入前全量校验、实时 Agent/状态聚合和部分后台操作继续用快照。不能宣称所有查询已迁移为 SQL 或端到端 O(1)。当前目录仍单进程独占，外部进程不得直接修改 SQLite。

新增 `tunnel_state_query_errors_total`，统计进程内失败的用户/资源 SQL 投影，正常 not-found 和 Close 后调用不计入。指标无用户/资源标签，不暴露身份或 SQL 错误详情。数据库不可读时当前用户鉴权也会拒绝，受保护的 metrics 入口可能 401；须结合进程/HTTP 可用性告警，恢复后查看保留计数。计数在进程重启时归零，不承诺存储不可用期间指标入口仍可访问。

## 验证

针对测试比较投影完整字段与原始状态，覆盖 JSON/SQLite、身份/切片复制、角色/组授权变更与撤销、禁用/关闭、并发跨实体版本一致性、durable SQL 回滚、部分读取失败及计数器；控制面测试确保错误不触发快照回退和旧 Repository 兼容。

完整端到端必须继续覆盖真实 Agent HTTP/上传/WS/SSE、直接/组/组织角色撤销、设备会话、原生 Keycloak OTP/状态同步及独立上游 OIDC 两后端。具体最新结果在对应 PR 验证记录中更新。

本地查询基准：1001 用户、1000 应用、一个相关角色和组，100 操作 × 3 轮。完整快照扫描用户为 3.14–4.28 ms/op、约 2.04–2.10 MB/op；包含关联授权/角色/组的 SQL 投影为 127–147 µs/op、约 6.32–6.38 KB/op。基准仅衡量一次查询，不代表请求全链路/生产容量；组数量和成员长度更大时需单独测量。原始数据：[user-queries.txt](../capacity/user-queries.txt)。
