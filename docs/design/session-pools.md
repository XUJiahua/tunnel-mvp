# 连接缓存身份的会话隔离模式

默认按应用共享 HTTP 连接池，适合 Cookie/请求级身份的应用。某些上游将认证身份缓存到 TCP 连接；若不同浏览器登录会话复用同一连接，可能出现身份混用。应用可选择 `connectionMode: "session"`，按应用 ID + 控制面登录会话密钥建立独立池，而不是仅按用户 ID。

隔离池只允许一个活动/空闲上游 TCP 连接，关闭 HTTP/2，以维持同一登录会话中的串行连接协商。健康探测使用另外的未认证池，不复用任何用户连接。密钥只用于内存索引，不写 URL、审计或指标；另一个设备/重新登录得到不同池。同一个控制面登录会话中的多个应用票据共享该会话的池。

登出、设备撤销、用户会话撤销立即关闭对应空闲连接池，已有请求仍由原有访问撤销机制取消。后台每分钟清理过期会话池；空闲连接 30 秒关闭。隔离池条目最多 1024 个，超出时逐出最近最少使用的条目并关闭空闲连接。应用编辑/迁移/模式切换移除所有关联池，模式切换也撤销已有应用票据。Agent 断线仍清理相关站点的所有池。

状态/备份 v9，SQLite v8 → v9 事务增加 connection_mode，旧应用默认共享；未知模式拒绝导入/写入。PATCH 不提供该字段时保留原模式，避免旧 API 客户端误改。创建/批量创建也可显式指定 session。

串行通道会产生队头阻塞。长时间下载、WebSocket 或 SSE 可能持续占用它，后续请求需等待；应把实时应用和连接缓存身份的遗留应用分开登记。此模式不执行 NTLM/Kerberos 协议，也不是 Windows 域认证产品兼容性保证；连接丢失、空闲过期或 LRU 逐出后，上游/浏览器需能重新协商。

验收使用真实 Agent 与按 TCP 连接缓存身份的上游：Alice/Bob 两个控制面会话分别发送认证和后续无认证请求，证明身份不互相继承、健康探测不污染身份、登出清理以及模式更改使旧票据失效。JSON/SQLite 存储升级、跨后端备份和浏览器操作均验证。实际 NTLM/Kerberos 仍需 Windows/AD 环境及目标产品验收。
