# Agent 远程收紧策略

## 本地授权始终为上限

Agent 需配置 `remotePolicy: true`（或 `--remote-policy` / `TUNNEL_REMOTE_POLICY`），且必须使用独立 instanceID。默认关闭；兼容 site-token 模式不能开启。控制面不能修改本地文件、开启此开关或扩大本地 ACL。

连接目标仅解析一次 DNS。对每个已解析 IP，使用同一个 host/port/IP 同时匹配本地和远程规则，两个条件都成立才建立到该 IP 的连接；不是分别解析后按主机名拼接授权结果。空远程规则拒绝所有目标。没有登记策略时返回确定版本的空策略，因此首次启用默认关闭目标访问。

## 获取、应用和失效

Agent 用绑定实例的 Bearer 凭据向同源 `GET /tunnel/policy` 请求；仅允许 HTTPS（回环例外），禁止重定向，3 秒超时，响应上限 64 KiB，严格 JSON/规则校验。每份策略最多 64 个规则，每条 1–64 个端口。版本为规则 JSON 的 SHA-256；相同内容不会重复重连，回滚到已知内容由管理员明确写回实现。

首次取得合法策略前不创建隧道。每 5 秒重新获取；内容变化时取消并等待旧隧道结束，再以新不可变规则建新隧道，旧 TCP/上传/WS/SSE 连接一并结束。不能仅更新新连接而保留之前放行的流。

临时获取失败保持最后有效策略，最后成功获取超过 30 秒后关闭隧道；检测最迟再加一次轮询间隔和 HTTP 超时（约 38 秒），不持久化无限有效的本地缓存。接口恢复后重新拉取并建隧道。进程重启必须重新拉取，不读取磁盘旧策略。单实例/站点禁用和轮换仍由控制面立即关闭连接，不等待轮询。

## 管理与可观测性

GET/PUT `/api/sites/{site}/agents/{instance}/policy` 限所属组织 `sites:manage`。PUT 只接收 allow 数组，版本由服务器生成；空数组是显式拒绝。登记状态 schema/backup v8，SQLite v7 的升级只推进版本并校验已有 JSON payload，防止旧二进制忽略新策略后覆盖丢失。

握手携带已应用策略版本，清单给出期望/自报应用版本；界面显示本地模式、待应用或已同步。它是运维遥测，不是对恶意客户端的远程证明。Agent 是本地网络访问的受信任执行者，本地运行者仍可换用其他客户端；此设计约束正常 Agent 的权限，不把已泄漏令牌变成可信主机证明。

审计记录策略版本和规则数，不记录令牌；策略本身属于授权状态备份。备份恢复可能恢复历史策略，事故后应重新复核。控制台仍保留清晰的本地显式启用说明。

## 验收

实际 Agent 验证远程 broad CIDR 不能放行本地未授权端口；空策略关闭已打开 SSE，恢复合法策略后新连接可达。模拟政策接口故障验证首次不连、失效后关闭真实隧道和恢复重连，覆盖无效版本/重定向拒绝。浏览器验证登记、策略编辑、初始拒绝、收紧、无效写入不改变状态。JSON/SQLite 交叉备份、旧版本升级和全量浏览器回归继续执行。
