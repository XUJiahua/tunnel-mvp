# 全部保留审计文件索引

第十层依赖监控/运维归档，替换当前文件末尾 2 MiB 的查询模型。JSONL 是原始记录，SQLite 是可重建索引；索引覆盖当前 audit.jsonl 和配置保留的全部轮转文件，不读取已被轮转删除的文件。

## 写入、轮转与恢复

正常审计先追加 JSONL，再同步添加索引；索引失败不会把已保存的原文件删除，设置 dirty 标记并增加 `tunnel_audit_index_errors_total`。下次查询先尝试从全部保留文件重建，无法重建返回 503，不能返回不完整索引冒充成功。

启动和轮转后在审计锁内、单 SQL 事务中重建。按最旧轮转文件到当前文件的追加顺序分配行 ID；原索引在提交前仍完整可读，不出现半套结果。保留期由原轮转数量/文件大小控制，索引不另截断为近期固定行数。重建耗时与保留日志总量有关；默认场景先确保完整性，后续容量验证评估增量轮转优化。

扫描每行最多 128 KiB，使用有界缓冲而不是对超长行分配无限内存。无效 JSON/UTF-8、非对象/不兼容字段或过大行跳过计数，原文件保留；全局管理员看到 skipped 警示。拒绝把符号链接作为索引来源。索引错误与原始日志写失败均计入指标，运维必须同时监控磁盘与采集链路；本层不承诺掉电情况下的外部审计系统 SLA。

## 查询与游标

`GET /api/audit` 保留 event、siteID、limit，增加 user、resourceID、since 和 cursor。字符串精确匹配，since 为 RFC3339，limit 为 1–500，响应同时限制约 2 MiB 记录数据；单页条数可能少于 limit，nextCursor 表示可继续。

参数绑定到 SQL，组织过滤在查询中强制加入。全局管理员可读全部；audit:read 角色只能读带本组织 organizationID 的记录。旧记录/无法归属记录的 owner 为 SQL NULL，绝不当作默认组织。全局文件数量/跳过计数不向组织角色返回。

按记录追加顺序倒序分页，不把本机时钟回拨误当新旧追加顺序。每次完整重建生成新 epoch，游标包含 epoch 与最后行 ID；遇到轮转/重启导致代际变化返回 409，客户端从最新重新查询，避免静默重复/漏行。新追加记录不改变既有游标，从旧游标可继续读更早数据。

UI 过滤显式提交，加载更多复用已应用过滤条件，避免用户编辑输入后将不同查询结果混在一页。支持操作者/资源/起始时间和移动布局。索引只覆盖仍在目录中的保留文件；长期审计仍需轮转删除前归档或日志采集。

## 数据格式

monitor.db schema v2 新增 audit_events 和 audit_index_state 以及组织/事件/操作者/站点/资源/时间索引。v1 → v2 单事务升级，不修改授权 schema/backup v6。运维归档 manifest 仍为 v1，接受 monitor schema v1/v2；恢复启动后重建派生索引，以归档中的 JSONL 为准。

## 端到端发现的 WebSocket 竞态

索引轮转测试延长了隧道生命周期，race 验证发现 remotedialer Ping/Pong 读回调与 Gorilla 数据写入并发设置 writeDeadline。采用固定源码版本的本地最小补丁，让写入方在既有写锁内设置 deadline，读回调只刷新读 deadline；到期的排队写入不再稍后发送，实际 socket 写入也受调用方 deadline 限制。保留协议/API/依赖版本与原许可。

## 验证

超过旧尾部范围的日志与轮转文件查询、组合过滤、游标无重漏、轮转/重启失效、2 MiB 页预算、默认/命名组织隔离、无效/超长/非 UTF-8 行处理、索引故障后明确拒绝与原文件重建、schema v1 升级。浏览器从真实旧轮转文件查询 250 条并分页、按资源过滤、组织审计员不读取旧全局记录、重启重新查询及手机布局。整个堆栈继续双后端、真实 Keycloak/Agent、运维归档恢复回归。
