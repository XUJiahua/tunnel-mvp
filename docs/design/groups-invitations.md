# 用户组与一次性成员邀请

第五批基于 `feat/session-lifecycle`，保持 stacked PR 的独立增量。本批统一单个工作区内的批量应用授权与成员入门；组织/租户边界、组织管理员和自定义管理角色另成下一层，不把用户组误当租户隔离。

## 权限计算

最终应用访问权是用户直接整站/应用授权与所有所属用户组整站/应用授权的并集。整站包含该站点以后新增的应用。用户组只授予应用访问，不授予管理员身份或管理 API 权限。

持久化用户记录仍只保存直接授权。鉴权时从一个一致状态快照计算组授权，避免把继承权限写回用户后无法收回。管理员编辑成员表单也只编辑直接授权；收回一条直接授权不能覆盖仍存在的组授权。

组创建、编辑、删除在访问写锁中提交，再按最新合并权限取消失去访问的 HTTP/WS/SSE。保留控制台会话和仍获授权应用的连接。新请求/票据使用实时权限，无法依靠旧应用 Cookie 绕过组修改。

删除用户、站点、应用或组时，在同一个状态事务内清理所有组/邀请引用。删除组保留成员账号，邀请中已不存在的组授权被移除。禁用账号仍优先于全部直接/继承授权。

## API 与可见性

| API | 权限/行为 |
| --- | --- |
| `GET/POST /api/groups` | 管理员列出/创建组 |
| `PATCH/DELETE /api/groups/{id}` | 管理员替换组名称、成员和授权/删除 |
| `GET /api/me/groups` | 成员只看自己所在的组和授权，不返回其他成员 ID |
| `GET/POST /api/invitations` | 管理员列出邀请状态/创建邀请 |
| `DELETE /api/invitations/{id}` | 管理员撤销未使用邀请 |
| `POST /api/invitations/inspect` | 用有效 bearer token 读取受邀用户名和到期时间 |
| `POST /api/invitations/accept` | 一次性 token + 新密码，创建 viewer 并登录 |

管理写入要求当前管理员会话及 exact Origin；新组和邀请均验证完整外键引用。普通成员不能调用管理入口。邀请 inspect/accept 同样要求浏览器 Origin，分别有 120/30 次每分钟全局上限，限制公开端点及 bcrypt 的工作量。

## 邀请生命周期

管理员指定未占用用户名、直接授权、待加入的组和 1–168 小时有效期（默认 72）。返回 192-bit 随机 token 构成的链接，明文只在创建响应/当前页面展示一次，持久化只保存 SHA-256。列表不返回 token 或 hash。

链接使用 `publicURL/#invite=...`。fragment 不发送给 HTTP Server；前端读取后立即从当前历史条目删除，再在 JSON 请求体中验证。页面也监听 hashchange，已打开的控制台粘贴同源邀请链接时仍会显示设密流程。Referrer 策略沿用 no-referrer，不记录完整链接或请求体。

受邀者确认用户名，自行设置 12–72 字节密码；不由管理员转交初始密码。接受时在一个状态事务内重新验证 token/有效期、创建 viewer、加入组并删除邀请，两个并发请求只有一个成功。成功后签发普通密码会话；即使已有账号登录，也会明确切换至受邀成员。

现有用户名不能被邀请覆盖。输入不能携带 role 等额外字段。失效、过期、已使用、被撤销的 token 返回统一失败，不能用于密码重置或 OIDC 绑定。组权限在使用时取当前状态，不冻结为邀请创建时的旧权限。

## 状态与迁移

模型新增 Groups 和 Invites 可选字段，旧 JSON/backup 缺省字段保持规范字节兼容。SQLite schema v3 增加按 position 排序的 groups/invites 表，各对象存 JSON payload，SQL 校验 JSON 合法性、主键和顺序，业务层验证 payload ID、所有用户/资源/组引用与 token/时间格式。这里有意保留聚合写模型，不宣称这些 JSON 内引用由 SQL FK 约束，也不宣称已完成增量 SQL 优化。

v1/v2 → v3 在目录锁内单事务完成 schema 添加、全量读取和域校验，失败回滚所有添加。新 backup v3 继续读取 v1/v2。正常重启和 JSON→SQLite 迁移保留未使用邀请。

**从历史 backup restore 时主动清空未使用邀请**，避免恢复已消费 token 的历史记录使链接重获效力。组、用户和已接受的组成员关系保留，管理员重新签发需要的邀请。备份含 token hash 及成员信息，应按凭据数据保护。

## 验证

- 双后端验证组授权、单应用/兄弟应用边界、直接与继承授权并集、即时 HTTP/WS/SSE 撤销和控制台保留。
- 邀请验证重复使用、并发单次消费、撤销、用户名冲突、角色固定与明文/散列不泄漏。
- SQLite v2 迁移、失败回滚、JSON payload/主键一致性、双后端持久化和 restore 不复活旧邀请。
- 浏览器创建组/邀请、fragment 设密、同一文档重复链接拒绝、真实 Agent 应用访问、组权限收回及手机布局；分别运行 JSON/SQLite。
