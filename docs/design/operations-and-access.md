# 管理、授权与运行能力设计

本文描述本批次已实现的行为。后续方向见 [实施路线图](../roadmap.md)，部署和操作见 [操作手册](../operations.md)。

## 1. 目标与边界

在单控制面架构中补齐可持续使用的管理能力：直接编辑资源、修改密码、应用授权、立即撤销长连接、Agent 本地 ACL 重载、可观测性和连接复用。继续复用 Go + remotedialer + Next.js 静态嵌入，不引入运行时 Node.js 或新外部依赖。

数据仍存放于 `state.json`，一次更新使用临时文件、fsync 和原子重命名；会话、票据、探测快照与连接池仍在内存中。本阶段没有引入数据库、分布式 Session Registry 或 SSO。

## 2. 权限模型与兼容性

用户增加 `serviceIDs` 数组。旧 JSON 没有此字段时按空数组处理，原有 `siteIDs` 的语义完全保留。

| 条件 | 可访问范围 |
| --- | --- |
| `role=admin` | 全部资源和管理接口 |
| `siteIDs` 包含所属站点 | 该站点全部现有及未来应用 |
| `serviceIDs` 包含应用 ID | 仅该应用 |
| 两种授权均存在 | 取并集 |
| 均不存在 | 拒绝 |

单独应用授权允许查看其父站点的名称、ID 和在线状态，但不暴露兄弟应用。应用列表、手动探测、启动票据、应用网关和健康快照均使用同一授权规则。目标是否符合本地网络策略仍由 Agent 独立判断。

成员权限 PATCH 提交的是完整替换集合，`siteIDs` 或 `serviceIDs` 缺省即清空对应集合；不是在原集合上追加。所有资源 ID 在同一次存储事务中验证。删除应用/站点同步清理用户的关联授权，避免留下悬空引用。

角色仍只有 `admin` / `viewer`；不提供通过 API 提升成员为管理员的能力。本地初始管理员通过自助改密维护密码，管理员重置接口只作用于成员。

## 3. HTTP 管理接口

所有 `/api/` 写请求沿用控制台 Session Cookie、JSON 内容类型及精确 Origin 校验。密码与凭据不进入审计。

| 接口 | 权限 | 请求 / 行为 |
| --- | --- | --- |
| `PATCH /api/sites/{id}` | 管理员 | `{name}`；保留站点 ID、令牌和隧道 |
| `PATCH /api/services/{id}` | 管理员 | `{name,url}`；所属站点保持不变 |
| `PATCH /api/users/{id}` | 管理员 | `{siteIDs,serviceIDs}`；替换成员授权 |
| `POST /api/me/password` | 当前用户 | `{currentPassword,password}` |
| `POST /api/users/{id}/password` | 管理员 | `{password}`；只重置成员 |
| `GET /api/status` | 当前用户 | 返回获授权应用的最新探测快照及探测间隔 |
| `GET /api/audit?event=&siteID=&limit=100` | 管理员 | 精确匹配过滤；limit 范围 1–500 |
| `GET /api/metrics` | 管理员 | Prometheus 文本指标，便于临时检查 |
| `GET /metrics` | 专用 Bearer 令牌 | 供监控采集；未配置时返回 404 |

沿用创建、删除、站点令牌轮换、应用启动及探测接口。应用目标仍必须是 HTTP/HTTPS 源地址，不支持路径、凭据、查询参数或片段。应用不能跨站点移动；跨站点迁移需新建应用并明确重新授权。

## 4. 会话与长连接撤销

`accessMu` 将安全相关变更与“校验并注册代理请求”串行化。网关在读锁内重新获取用户、应用和授权，注册该请求的取消函数，再释放锁转发；不在网络转发期间持锁。

每个活跃请求登记用户 ID、控制台 Session Key、应用 ID、到期时间及取消函数。请求 Context 的截止时间取控制台会话和应用访问会话的最早到期时间。Go ReverseProxy 会在 Context 取消时终止 HTTP/SSE，并关闭已 Upgrade 的 WebSocket 上游和浏览器连接。

| 事件 | 撤销行为 |
| --- | --- |
| 退出控制台 | 删除当前控制台 Session，关闭该 Session 派生的活跃请求 |
| 自助改密 / 管理员重置 / 删除成员 | 删除该用户全部 Session，关闭该用户全部活跃请求 |
| 修改成员权限 | 保留控制台登录；关闭已失去授权的应用请求；新请求实时校验 |
| 应用访问 Cookie 或控制台 Session 到期 | 请求 Context 到期，关闭长连接 |
| 修改应用目标地址 | 撤销该应用所有票据和访问 Cookie，关闭请求并淘汰连接池 |
| 仅修改应用名称 | 保留票据和连接 |
| 删除应用 | 撤销应用票据、连接和监控快照 |
| 删除站点 / 轮换令牌 | 关闭站点隧道；站点删除还清理所属应用 |

修改密码需要 12–72 **字节**。自助修改必须验证当前密码，bcrypt 结果原子持久化成功后才撤销会话；持久化失败不会报告成功。登录校验与密码变更使用同一顺序锁，避免旧密码校验结果在改密完成后创建新 Session。

应用目标修改保留公网域名，因此浏览器里原应用自身的 Cookie 也仍可能存在。网关只撤销自己的访问凭据，不删除未知的第三方 Cookie。将 ID 复用于完全无关应用时，应新建应用以建立新的浏览器源。

## 5. 连接池与隔离

连接池以应用 ID 为键，绑定完整应用描述（站点、目标及名称）。不同应用、站点、目标之间不共用 Transport；同一应用的用户可以复用 HTTP 连接，但每次请求独立鉴权，不向上游发送控制台/网关 Cookie。

参数：每应用最多 32 个全局空闲连接、每目标最多 16 个空闲连接、64 个并发连接，空闲回收 30 秒；保留现有 10 秒 Dial/TLS、30 秒响应头超时。WebSocket/SSE 仍使用流式代理。达到连接上限时由 Transport 排队并受请求 Context 约束。

目标变更、资源删除、Agent 断开和令牌轮换都会清除相应空闲池；已使用的连接由请求撤销或底层隧道关闭终止。连接池不跨 Agent 重连复用。手动和自动 HEAD 探测复用同一应用池。

当前不提供“每用户独占连接”模式。依赖 NTLM 等连接绑定身份的上游应用需要额外适配。连接复用验证不等于已获得生产容量结论。

## 6. Agent ACL 重载

`agent --watch-config -c agent.json` 每 2 秒重新读取有效配置，继续遵循 CLI > 环境变量 > 文件优先级。只有完整配置和全部 ACL 校验成功，且 `siteID/serverURL` 未变，才比较并替换 ACL。

替换通过取消旧 Agent 运行循环、等待退出、用新策略重连完成，进程 PID 不变。已有数据流断开，防止旧规则下的连接或 Server 空闲池继续绕过收紧后的 ACL。短暂离线期间，新请求可能失败，客户端需重试。无效文件保留旧策略，并对重复错误抑制日志。

仅 ACL 支持此重载；站点身份、Server 地址、令牌、日志配置变更应重启进程。不远程下发 ACL，控制面不能扩大 Agent 本地白名单。

## 7. 探测、指标与告警

CLI 加载配置时默认每 60 秒探测；`probeIntervalSeconds=0` 关闭。启用时范围 10–86400 秒。每轮从当前注册表读取应用，4 个工作协程并发执行 HEAD，请求最长 14 秒，前一批完成后才处理下一批。

- `reachable=true`：成功收到 HTTP 响应头，包括 401/403/405/5xx。
- `healthy=true`：HEAD 返回 200–399。它只是状态码判定，不代表业务验收成功；认证入口可能正常返回 401。
- 不跟随跳转，不带用户 Cookie，不支持自定义业务探测路径。
- 每应用只保留最新快照；返回中含探测开始时间，控制台悬停可查看。
- 应用修改/删除后旧任务的结果被丢弃；同一应用的较旧结果不能覆盖较新的结果。
- 首次探测或 reachable/healthy 状态变化写入 `health_changed` 审计；每次手动探测仍记录完整结果。

指标包含代理请求/传输错误计数、完成探测数、活跃请求数、站点在线状态、应用可达性/状态码健康判定/最后探测时间/耗时。进程重启计数器清零。标签使用资源 ID，不携带用户名、URL、Cookie 或令牌。

监控令牌通过 `TUNNEL_METRICS_TOKEN` 注入，至少 32 字节，只授权读取 `/metrics`，不等同用户或 Agent 凭据。仓库提供 Prometheus 采集和告警规则示例；告警投递由现有 Prometheus/Alertmanager 负责，本程序不发送通知。

## 8. 审计

`audit.jsonl` 达到默认 20 MiB 时轮转，保留 5 个历史文件。大小与保留份数可配置。单条记录可能使文件略超阈值，下次写入前轮转。保持新文件 0600 权限；轮转失败记录错误并继续尝试写入当前文件。

查询接口只扫描当前文件最后 2 MiB，返回最多 500 条过滤结果，按文件顺序倒序；若截断点位于一行中间，跳过首个残行。完整历史应由外部日志采集系统收集，包括 `.1` 至 `.N`。审计查询接口不提供任意文件路径访问。

## 9. 验证方式

真实 Agent 集成测试覆盖应用粒度隔离、编辑后的 ID/持久化/目标切换、旧访问凭据撤销、密码修改/重置、WebSocket/SSE 多种撤销路径、到期断连、HTTP 503 的状态区分、池复用、监控鉴权与审计轮转。ACL watcher 测试实际修改文件，验证坏配置不生效、收紧规则后池不能绕过。

浏览器测试覆盖站点/应用编辑、整站授权转为应用授权、兄弟应用隐藏、审计查询、改密重登和重置后的失效。部署前执行 `make build`、`make test` 和 `cd web && pnpm run test:e2e`。
