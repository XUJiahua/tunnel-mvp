# Agent 签名升级与回滚

## 授权模型

升级通过本机配置的独立 supervisor 启用。发布公钥、更新 URL、当前版本序号下限和私有安装目录由主机操作员固定，控制台/站点令牌不能更改。发布私钥留在离线签名环境，不进入配置、控制面数据库或 Agent 主机。默认直接运行 `agent` 时不下载/执行更新。

Ed25519 签名覆盖完整 payload 字节，内含格式、单调 sequence、精确版本、失效时间和平台 raw executable 的 URL/大小/SHA-256。每个平台最多一个文件，六平台可共用一份 manifest；最大单文件 128 MiB，签名外层 128 KiB，最长有效期 7 天。HTTPS（回环测试例外）、禁止重定向/查询参数/URL 凭据；下载没有站点 Bearer 头。CDN 需提供直接文件 URL。

主机持久化最高 sequence，低于/等于该值不再自动安装；回滚不降低它。首次装机默认下限 0，只代表尚未安装签名版本；应以 `--minimum-sequence` 固定引导版本的发布序号。合法新版本可恢复旧内容但必须由签名方发布更高序号。过期、错误签名、重复平台、错误大小/哈希或缺少当前平台均保持当前 Agent 运行。

## 安装与恢复

私有目录以进程级文件锁独占，保存 current、previous、candidate 和 0600 的 journal；拒绝符号链接/非普通文件。初次引导仅从操作员显式选择的本地可信二进制复制，不把网络下载当作信任根。后续启动按 journal 重新校验 current。

1. 当前 Agent 继续运行时下载并校验 candidate，fsync 落盘。
2. 停止并等待旧 Agent 退出；写 pending 日志和已接受的最高序号。
3. 将原 current 复制到 previous 后 fsync，原子发布 candidate 为 current。
4. 启动候选 Agent，等待 JSON `site tunnel connected` 事件，且事件中的实际构建版本与签名版本一致。
5. 成功后将新/旧摘要和版本写入已提交 journal。失败先停止候选、恢复经校验的旧二进制，再启动旧 Agent；失败序号不重复尝试。

启动遇到 pending 始终回到日志中的旧 current；如果既找不到匹配的 current 又找不到匹配的 previous，则停止并要求修复，不执行未知文件。父进程停止时先停止子进程。当前 Agent 退出会重启，重复退出或启动未就绪时尝试经校验的 previous；如回退版本也无法连通则退出，让服务管理器/操作员处理。

`agent rollback` 仅在 supervisor 已停止、能独占目录锁时执行；交换当前和已验证上一版本，并保持高水位序号。失败更新的恢复可能耗尽原回滚槽，下一次健康升级会重新建立槽；不能承诺任意历史版本链。

## 运维和限制

控制面中已有的实例自报版本用于观察，但更新就绪检查来自本地受信任二进制日志。就绪只证明隧道连接，不证明业务兼容；发布前仍需真实应用验收。升级期间会中断该实例的 HTTP/上传/WS/SSE，应先具备至少两个可达实例，分批安排各主机的更新 URL/发布时间，已有请求不重放。

Supervisor 自身不在线替换；主机服务管理器保持父进程存活，Agent 子进程才是管理对象。CLI 参数中的站点/ACL 覆盖不转发，使用配置文件或环境变量；可转发本地配置监视。发布私钥、公钥更换和服务管理器部署仍是操作员职责，不自动上传私钥或创建发布标签。

Unix 路径使用文件/目录 fsync；Windows 不支持目录 fsync，停止子进程后重命名文件。六平台交叉编译不等于 macOS/Windows 的服务管理器和断电恢复实机验证，这些仍需目标环境验收。

## 验收

单元/race：签名篡改/错误公钥/过期/重定向/平台/大小/摘要、目录锁、篡改 current、pending 恢复、回滚与高水位防重放。浏览器用真实编译的两个 Agent 版本：登记实例、签名升级、1 MiB 上传、SSE 中断、合法签名但无法启动的候选自动恢复、重启不重装失败版本、成功后离线回滚，并检查实际版本及应用可达性。
