# 组织角色的有界委派

新增组织能力 `roles:manage`。全局管理员可将其和需要委派的其他能力放入组织角色，再分配给组织操作员。操作员只能在自己的组织创建、修改、删除、分配权限集合不超过自身当前集合的角色；既检查请求的新权限，也检查被修改角色的原有权限，不能通过先删减高权限角色来接管它。

分配/清除成员角色时同时检查：成员非全局管理员、同组织、成员原角色权限不超过操作者、目标角色权限不超过操作者。权限相同的同级组织角色可互相管理，这是显式委派的能力；需要隔离团队管理者时应分组织或使用不同能力上限。可将 roles:manage 自身继续委派，但不能借此新增其他能力。

权限比较使用访问写锁内重新认证得到的当前权限。全局角色收回、会话撤销与后续写请求排序，旧 cookie 不保留委派能力。编辑/删除角色撤销所有持有者的会话与 HTTP/WS/SSE；分配变更也撤销目标成员所有设备。自我降权允许执行，成功后自己也需重新登录。

角色管理与成员账号管理分开：roles:manage 不授予重置密码、改身份、禁用、删除成员等能力；组织角色账号的这些修改仍受原有全局管理员保护。组织创建/删除、全局管理员、全局设备与指标仍为全局能力。

`GET /api/role-members` 只返回所属组织的最小角色分配目录（ID、用户名、组织、角色和可管理标记），没有密码哈希、身份绑定或设备信息；不需要额外授予 members:manage。角色列表标注 manageable，只向非全局操作者返回其能委派的能力选项；不可管理的角色/成员禁用 UI 操作，服务端独立校验。

状态/备份 v10，以防旧版本忽略新的 roles:manage 语义。SQLite v9 → v10 不改表结构，在事务中校验并提升版本。旧角色不会自动获得新能力；需要全局管理员显式委派。

验收覆盖跨组织、增加未持有能力、修改/删除高权限角色、清除高权限成员角色、给普通成员分配高权限角色、全局管理员与组织创建越权，以及自身降权后的旧会话拒绝。浏览器以组织操作员创建/分配子角色，成员通过真实 Agent 建立 SSE，操作员收回应用能力后流关闭且成员退出。
