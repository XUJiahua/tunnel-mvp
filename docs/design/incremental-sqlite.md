# SQLite 增量写入

Repository 仍提供经过整体验证的不可变授权快照，读取继续使用内存模型。原 SQLite save 每次删除/重写全部实体和授权关系；本批以最近已提交的 SQL 行及授权关系缓存计算差异，只替换变化的实体、位置和 grant 列表。

缓存保存独立的参数行/JSON payload 和复制后的 grant 切片，不引用回调可变结构。成功 commit 后才发布新缓存；失败不推进缓存或内存读模型，下一次更新仍相对上次已提交数据计算。启动/离线恢复从已验证数据库重建缓存，不依赖磁盘外的历史状态。目录锁继续排斥其他写进程，直接在运行中修改 SQLite 不受支持。

变化行先全部删除，再按新状态重插入，使用户名/issuer-sub 唯一值互换和 position 重排都在一个事务内成立。外键使用事务级 `defer_foreign_keys=ON` 延后到 commit 检查，始终不关闭 foreign_keys；未变化的 grant 行可保留对同一主键的引用，最终孤立引用仍不能提交。授权关系仅在对应用户的 grant 数组变化/删除时更新；单纯改密或名称不重写授权表。

删除或重排可能改变后续实体的位置，相关行仍需更新；不承诺所有删除操作为 O(1)。领域验证、快照复制、差异生成仍为 O(N)，这是单进程内存读模型的优化，不是共享数据库、多写节点或控制面 HA。当前 schema/backup v10 不变，没有新表布局。

验收：SQL 触发器记录实际被改动表/ID，证明稀疏改名不碰无关用户/服务/授权；no-op 无行写入、仅 grant 变化不重写实体；唯一值互换、顺序重排、父子同时删除、事务失败与后续重试、回调保留指针修改后下一次更新、所有历史 schema 升级及交叉备份恢复。控制面与浏览器继续对 JSON/SQLite 跑完整流程。
