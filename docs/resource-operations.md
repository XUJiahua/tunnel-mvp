# 应用迁移、域名和批量操作手册

## 带路径应用

应用内网地址可填写 `http://internal:3000/grafana/`。公网入口将保留 `/grafana/`，应用自己需要配置该子路径和正确的外部 URL。只支持普通 ASCII 路径段，不接收 query、fragment 或 URL 中的账号密码；凭据继续在应用登录页输入。

从控制台打开后，验证登录、静态文件、重定向、上传、WS/SSE。如果应用跳到 `/login` 或 `/assets` 并收到 404，检查应用的子路径配置；网关不会改写任意 HTML/JS。健康探测默认对已登记目标执行 HEAD。

## 自定义访问域名

1. 全局管理员为域名配置 DNS，使其指向现有边缘入口；为域名配置有效 TLS 证书，并确保该 host 转发到控制面网关且保留 Host。
2. 在应用创建/编辑表单填“自定义访问域名”，例如 `reports.customer.example`。只填主机名，scheme/端口沿用 accessURL。不能使用控制台域或内置访问域的父/子域；开发 HTTP 回环可用 `reports.customer.localhost`。
3. 保存后原应用访问会话失效。从控制台重新打开，验证目标 hostname、TLS、登录和跳转；不使用绕过证书校验的方式代替验收。
4. DNS/TLS 未准备好时先留空；空值恢复 ID 访问域名。组织应用管理员不能变更绑定。

边缘代理必须覆盖新 host，而不仅是 `*.apps.example`。本批不自动创建 DNS/证书。不要把旧域名重新分配给无关应用而保留旧浏览器 Cookie；更换安全域使用新应用/新域名或先清理浏览器数据。

## 单应用迁移

在应用“编辑”选择同组织的“迁移目标站点”。先在新 Agent 配置好目标 CIDR/端口/主机名 ACL，并检查相同内网地址在新站点是否代表同一应用。保存会关闭现有连接并收回访问票据。

| 原授权 | 迁移后 |
| --- | --- |
| 原站点整站授权 | 不再覆盖迁出的应用 |
| 新站点整站授权 | 开始覆盖迁入应用 |
| 单应用直接或组授权 | 跟随应用 ID 保留 |
| 全局管理员/本组织全部应用角色 | 仍具备访问权，但需重新打开签发网关会话 |

跨组织迁移拒绝，需要重新登记与重新授权。目标实际变成无关应用时也应新建应用，以隔离浏览器内的第三方 Cookie。

## 批量应用

应用管理角色进入“批量应用”。批量添加可增加表单行，最多 100 个；任意行无效则全部拒绝。列表勾选应用，选择目标站点后“迁移所选”，或“删除所选”。确认前核对应用数量与站点。

迁移/删除提交后立即关闭全部受影响连接。迁移后重新探测与打开应用；删除同时清理直接/组/邀请引用。存在其他组织或未知 ID 时整个批次失败，不会只执行可见部分。API 清单见 [设计](design/resources-targets.md)。

升级使用 schema/backup v5，按 [存储手册](storage-operations.md)先停止并备份。Agent 建议同步升级以修正快速取消时的关闭顺序竞态；旧 Agent 协议仍兼容，但不包含此修正。
